- **Upside**: `load_entity_schemas()` is a fully-parsed, uncapped code path — no `GUIDE_MAX_CHARS` truncation risk exists there, so this shift eliminates that failure mode structurally rather than by raising a constant. It also removes the drift risk of a hand-maintained prose schema silently disagreeing with itself over time.
- **Cost**: `schema.md` in this KB carries real content beyond field shape — page-shape philosophy (Compiled Truth vs. Timeline), the inline citation convention, naming rules — none of which reduces to wakil's per-type YAML. - **Generalization risk**: wakil's built-in entity schema was transcribed from *this* KB's own conventions, so for this KB specifically the two are already meant to match — low-risk to consolidate here. For a different KB with materially different entity conventions, forcing wakil's built-in schema as the sole authority makes one user's opinion binding on everyone; that's a bigger design commitment than fixing this one KB's truncation problem.
