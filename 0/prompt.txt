**ADR/doc fit:**
- Read `docs/adr/0018-mcp-interface.md` in full since this touches the MCP server it defines. This PR does not reopen or contradict it — no tool's behavior, signature, or the prepare/apply mechanism changed; it's a pure code-organization move within the same file ADR 0018 already describes.
- One naming nit worth a comment (not blocking): ADR 0018's own text groups `git_summary`/`git_history` under "**Read tools**" together with `status`/`search`/.../`skills_list` (all 11 listed in one category, `docs/adr/0018-mcp-interface.md` line 48-51). This PR introduces a `_register_git_tools` function as a category distinct from `_register_read_tools`, which is a finer split than the ADR's own taxonomy. It's a reasonable engineering choice (git operations are conceptually distinct from KB-content reads), but it means the code's grouping and the ADR's prose grouping now disagree at the naming level. Worth either a one-line note in the ADR/`docs/DEVELOPMENT.md` acknowledging the finer split, or simply naming it something that doesn't imply a new formal category (e.g. folding it into `_register_read_tools` or calling it out as a sub-grouping) — cosmetic, but exactly the kind of small drift that compounds if a third contributor invents a fourth ad hoc category later.
- `docs/DEVELOPMENT.md`'s existing gotcha entry ("MCP tools live in `mcp/tools.py` as plain functions; `mcp/server.py` wraps them in closures for FastMCP registration") still holds true after this PR — the closure-per-tool mechanism it describes is unchanged, just distributed across four functions instead of one. No doc update is strictly required, though the entry could optionally mention the four-way split for a reader skimming `server.py` for the first time.
- README's MCP section (`README.md` line 257-286) documents `wakil mcp serve` at the user-facing level only; nothing there references `build_server`'s internal shape, so no README update is needed and none was made.
