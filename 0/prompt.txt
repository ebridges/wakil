## 1. New module: `src/wakil/app/context_references.py`

This module owns everything about turning raw `--context`/`--context-file` CLI input into one resolved string: reference parsing, per-piece expansion, binary detection, token estimation, and the budget check. It has **no dependency on `ingest_service.py`** (avoids a circular import and keeps this a standalone, independently-testable unit) and depends only on `wakil.integrations.web` and `wakil.knowledge.markdown` (for the heading slicer, see §4).

```python
"""Resolve --context/--context-file CLI input into one context string,
expanding @file:/@url:/bare-@ references. Pure CLI-support layer: nothing
here is imported by wakil.app.ingest_service, and prepare_capture/
prepare_enrichment are untouched."""

import mimetypes
import re
from dataclasses import dataclass
from pathlib import Path

from wakil.integrations.web import Article, FetchError, fetch_article
from wakil.knowledge.markdown import slice_heading_section

class ContextResolutionError(RuntimeError):
    """A --context/--context-file value could not be resolved. Callers
    (main.py) must abort the whole command before any capture/enrichment
    work happens -- never partially apply."""

# --- constants -------------------------------------------------------------
CHARS_PER_TOKEN = 4                      # rough heuristic, no tokenizer dep
MODEL_CONTEXT_WINDOW_TOKENS = 180_000    # one assumed constant, v1 scope
WARN_BUDGET_FRACTION = 0.25
HARD_BUDGET_FRACTION = 0.50

# suffix -&gt; language tag for fences; also doubles as the "known text
# extension" override for binary detection AND the bare-@ "recognizable
# extension" allowlist (single source of truth per spec's reuse note)
_LANGUAGE_BY_SUFFIX = {
    ".md": "markdown", ".markdown": "markdown", ".py": "python",
    ".json": "json", ".yaml": "yaml", ".yml": "yaml", ".toml": "toml",
    ".txt": "", ".sh": "bash", ".rst": "", ".csv": "", ".srt": "",
}

_REF_RE = re.compile(
    r'@(?:'
    r'(?P&lt;kind&gt;file|url):(?:"(?P&lt;qval&gt;[^"]+)"|(?P&lt;val&gt;\S+))'
    r'|(?P&lt;bare&gt;\S+)'
    r')'
)

@dataclass
class ExpandedBlock:
    label: str
    content: str  # ready-to-insert fenced block, incl. token-count header

def estimate_tokens(text: str) -&gt; int:
    return len(text) // CHARS_PER_TOKEN

def expand_piece(raw_text: str, workspace_root: Path) -&gt; str:
    """Expand all @file:/@url:/bare-@file references in one raw context
    piece. Returns the piece with reference tokens stripped and a
    '--- Attached Context ---' section appended (only if &gt;=1 block
    resolved). Raises ContextResolutionError on any failure."""
    ...

def resolve_context(
    *, context: list[str], context_files: list[Path], workspace_root: Path,
) -&gt; tuple[str | None, list[str]]:
    """Assemble --context values (in order) then --context-file contents
    (in order, each file's full text read as one piece before expansion),
    each piece @-expanded, joined with '\\n\\n---\\n\\n'. Returns
    (None, []) when both lists are empty -- so prepare_enrichment's
    capture-time-context fallback still fires. Raises
    ContextResolutionError on any reference-resolution failure or when the
    assembled total exceeds HARD_BUDGET_FRACTION of the assumed window;
    returns non-fatal warnings (e.g. WARN_BUDGET_FRACTION exceeded) for the
    caller to print."""
    ...
```

Internal helpers (private, `_`-prefixed, in the same module):

- `_parse_ref_value(raw: str) -&gt; tuple[str, int|None, int|None, str|None]` — given the unquoted/quoted `file:` value, split off `#heading` (rpartition on last `#`) or `:start-end` (regex `^(.*):(\d+)-(\d+)$`), mutually exclusive per spec; returns `(path_str, line_start, line_end, heading)`.
- `_looks_like_file_reference(value: str) -&gt; bool` — `"/" in value or Path(value).suffix.lower() in _LANGUAGE_BY_SUFFIX` — governs whether a bare `@value` is treated as `@file:value` or left as untouched literal text.
- `_is_binary(path: Path) -&gt; bool` — if suffix in `_LANGUAGE_BY_SUFFIX`, not binary (override); else `mimetypes.guess_type` — if it confidently says `text/*`, not binary; otherwise sniff first 4096 bytes for `b"\x00"`.
- `_resolve_file(path_str, line_start, line_end, heading, workspace_root) -&gt; ExpandedBlock` — resolves relative-to-`workspace_root`, `.resolve()`, containment check (`relative_to(workspace_root.resolve())`, `ValueError` -&gt; `ContextResolutionError("... is outside the workspace")`), existence check, `_is_binary` check, read text, apply `slice_heading_section` (raise if `None` returned — "no matching heading") or line-slice (`lines[start-1:end]`, clamp bounds, raise if `start &gt; end` after clamping), build fenced block: `f"📄 {label} ({estimate_tokens(sliced)} tokens)\n\`\`\`{lang}\n{sliced}\n\`\`\`"`.
- `_resolve_url(url: str) -&gt; ExpandedBlock` — `fetch_article(url)`, catch `FetchError` → `ContextResolutionError(f"could not fetch {url}: {exc}")`, same fenced-block shape (no language tag).

`expand_piece` implementation strategy: use `_REF_RE.sub(callback, raw_text)` where `callback` is a closure appending to a local `blocks: list[ExpandedBlock]` list and:
- for `kind == "file"` or `kind == "url"` (or bare classified as file-like): resolve, append block, return `""` (strips the token from visible text);
- for bare classified as literal: return the original matched text unchanged (leaves it in place).

After the substitution pass, if `blocks` is non-empty, append `\n\n--- Attached Context ---\n\n` + `"\n\n".join(b.content for b in blocks)` to the stripped/stripped-and-`.strip()`ped text; otherwise return the stripped text as-is.

## 4. Heading-section slicer

**Location recommendation: `src/wakil/knowledge/markdown.py`**, not a new module and not inside `context_references.py`. Rationale: it's a pure Markdown-text operation (no file I/O, no workspace/CLI concerns) and this file already owns exactly this kind of heading-regex logic (`_H1_RE`, and `ingest_service.py`'s own `_HEADING_RE`/section-walk pattern at line ~1274 is a close analog worth mirroring, though it lives in the wrong module for reuse). Keeping it in `markdown.py` avoids a third module for one function and matches CLAUDE.md's "avoid speculative abstraction."

```python
_HEADING_LINE_RE = re.compile(r"^(#{1,3})\s+(.+?)\s*$", re.MULTILINE)

def slice_heading_section(text: str, heading: str) -&gt; str | None:
    """Body text under the first H1-H3 heading whose title matches `heading`
    (case-insensitive, trimmed), up to the next heading of equal-or-
    shallower level (same or fewer '#'), or end of text. None if no H1-H3
    heading matches."""
    target = heading.strip().casefold()
    matches = list(_HEADING_LINE_RE.finditer(text))
    for i, m in enumerate(matches):
        if m.group(2).strip().casefold() != target:
            continue
        level = len(m.group(1))
        newline_idx = text.find("\n", m.end())
        start = newline_idx + 1 if newline_idx != -1 else len(text)
        end = len(text)
        for later in matches[i + 1:]:
            if len(later.group(1)) &lt;= level:
                end = later.start()
                break
        return text[start:end].strip("\n")
    return None
```

Key logic points: only H1-H3 are heading candidates (regex `#{1,3}`, not `#{1,6}`, matching the spec exactly — H4+ neither anchors nor bounds a section). The boundary is the next heading with `len(#) &lt;= level` (strictly shallower *or same* level ends the section; a deeper heading, e.g. an H4 or an H3-nested-under-a-matched-H2, stays inside the sliced content). `expand_piece`/`_resolve_file` imports this from `wakil.knowledge.markdown` and treats a `None` return as a `ContextResolutionError` ("heading '&lt;name&gt;' not found in &lt;path&gt;").

## 6. CLAUDE.md scope-boundary check

- **Per-provider/per-model context-window table**: confirmed out of scope. One `MODEL_CONTEXT_WINDOW_TOKENS` constant matches "smallest useful version" and "avoid speculative abstraction" — nothing here quietly needs more; the constant is trivially bumped or made per-provider later if it ever matters.
- **Token estimation**: `len(text) // 4` with no tokenizer dependency is correct scope — adding `tiktoken` or similar would be new infra for a rough budget guard, which the project's dependency list (httpx/BeautifulSoup/frontmatter/etc., no tokenizer) doesn't currently include and shouldn't need to.
- **Binary detection**: `mimetypes` (stdlib) + null-byte sniff, no `python-magic`/`filetype` dependency — correctly scoped, avoids a new dependency for a guard-rail feature.
- **Heading-section slicing**: a single regex-based pure function is consistent with (not a step up in complexity from) the existing `_H1_RE`/`_HEADING_RE` precedents already in the codebase — not a new markdown-AST parser, even though `markdown-it-py` is already a project dependency. Correctly scoped.
- **Two flagged-but-intentionally-out-of-scope rough edges** worth a one-line mention in the PR description rather than fixing now: (1) the mini `@`-reference syntax has no escaping for quotes-within-quotes or literal `#`/`@` inside a quoted path; (2) unquoted `\S+` token matching can swallow trailing sentence punctuation immediately after a reference (e.g. `@file:notes.md.` picks up the trailing `.` as part of the path and will 404). Both are consistent with "keep changes small" — fixing them would require a heavier parser for a marginal edge case.
- **Confirmed**: no `CaptureProposal`/`EnrichmentProposal` field additions, no `prepare_capture`/`prepare_enrichment` signature changes — the whole feature is additive and CLI-layer-contained, which is the cheapest possible integration into the existing service layer.
