2. Key Technical Concepts:
   - wakil's two-step ingest architecture: Step 1 capture (`wakil ingest`, fully deterministic, no model) → Step 2 enrichment (`wakil enrich`, a fixed code-sequenced DAG of model calls).
   - The enrichment DAG, now 3 nodes: (1) extraction — `_run_extraction`, produces `ExtractionOutput`/`proposed_note`; (2) entity resolution — `_run_entity_resolution`, produces `EntityResolutionOutput` (create/update/skip per entity), followed deterministically by stub-building, link-reconciliation, and now entity-updates; (3) **entity updates** (new this session) — `_run_entity_updates`, produces `EntityRevisionOutput`, merged deterministically into existing files.
   - Skill resolution pattern (`wakil.skills.resolver`): ordered roots (WAKIL_SKILL_PATH → kb-local → user → builtin), whole-directory/whole-file shadowing, first-match-wins, no partial overrides, no cross-root merging — this exact pattern was mirrored twice more this session (entity schema resolution, page-shape template resolution).
   - Entity schema system (`src/wakil/schema/entities/*.yaml`, `src/wakil/schema/loader.py`): `EntitySchema` Pydantic model with `type`, `directory`, `category` (identity/document/hybrid — drives `name:`/`title:` frontmatter rule), `page_shape` (NEW — drives narrative body structure, a genuinely separate axis from `category`), `fields: dict[str, FieldSpec]`, `origins` (source-only sub-schemas).
   - Page-shape system (NEW): two body-shape templates — `compiled-truth-timeline` (accumulating subject: Compiled Truth prose + append-only Timeline/Log) and `single-occurrence` (one dated event: Summary/Key Decisions/Action Items/Discussion Notes, sections optional per type). Templates live in `src/wakil/schema/templates/*.md`, resolved via the same 3-tier precedence pattern (no WAKIL_SCHEMA_PATH-equivalent override tier yet, deliberately deferred).
   - Real entity-page structure discovery: actual files have **no explicit `## Compiled Truth` heading** (implicit prose after H1); the only reliable structural anchor is `## Timeline / Log`; files also carry a trailing block of auto-generated flat backlink bullets (`- **date** | Referenced in [title](path)`) after the dated `### date — ...` entries.
   - "Never silently overwrite" / staleness-guard pattern, first established in `schema_migrate_service.apply_migrations` (re-read immediately before write, skip if content changed since planning) — now mirrored in `apply_enrichment` for `entity_updates`.
   - Rich console markup escaping (`rich.markup.escape`) — needed whenever untrusted/bracket-containing dynamic text (e.g., wikilinks `[[path|display]]`) is interpolated into an f-string passed to `console.print()`, since Rich parses bare `[...]` as style tags.
   - `FakeClient` test pattern: a scripted-response stand-in for `ModelClient`, queue-based, asserts the queue isn't empty on each `.complete()` call — used across `test_ingest_service.py` and `test_entity_resolution.py`, both needed updating for the new 3rd DAG-node call.
   - Pydantic contracts pattern (`wakil.llm.schemas`): every model call has a matching `BaseModel` contract; `model_json_schema()` is injected into the system prompt so what the model sees and what gets validated never drift; `complete_with_contract()` does validate + one retry + visible failure (`ModelContractError`).
   - `uv run pytest -q`, `uv run ruff check`/`uv run ruff format` as the standard verification loop throughout.
   - A **known, pre-existing baseline of 19 test failures** (in `tests/unit/test_skills_resolver.py`, `tests/integration/test_skills_cli.py`) caused by a concurrent agent's unrelated in-flight work on `src/wakil/skills/models.py` (a `description` field made required without updating fixtures) — explicitly NOT to be touched/fixed, only used as a baseline to confirm no *new* regressions.
