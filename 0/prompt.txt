## Part 1: SCHEMA.md / RESOLVER.md

### 1. Where they're loaded

The only loader is `load_workspace_guides` in `src/wakil/app/ingest_service.py:1351-1363`:

```python
def load_workspace_guides(config: WorkspaceConfig) -&gt; dict[str, str]:
    """SCHEMA.md (page shape) and RESOLVER.md (routing) excerpts, when present."""
    guides = {}
    for name in ("SCHEMA.md", "RESOLVER.md"):
        path = config.root_path / name
        if path.is_file():
            try:
                guides[name] = path.read_text(encoding="utf-8", errors="replace")[
                    :GUIDE_MAX_CHARS
                ]
            except OSError:
                continue
    return guides
```

`GUIDE_MAX_CHARS = 4_000` (line 71) — a hard truncation with no warning; `docs/TROUBLESHOOTING.md:52-60` documents this as a known gotcha.

It's called once, in `prepare_enrichment` (line 407: `guides = load_workspace_guides(config)`), then threaded into both `_run_extraction` (line 423) and `_run_entity_resolution` (line 456), which pass it as `guides=guides` into `build_extraction_prompt` (line 606) and `build_resolution_prompt` (line 633).

There's a second, independent SCHEMA.md-specific reader: `transcript_frontmatter_template` (`ingest_service.py:1370-1402`), which regex-scans SCHEMA.md for a fenced yaml block under a heading mentioning "transcript"/"source" and uses it to build the raw-capture frontmatter template (`_transcript_metadata`, line 1457) — this is a *separate* mechanism from `load_workspace_guides`, used only at capture time, not enrichment.

class EntitySchema(BaseModel):
    type: str
    directory: str | None = None  # canonical directory, None = no single home

### 4. Real SCHEMA.md/RESOLVER.md content vs. the YAML catalog

- `tests/fixtures/kb/SCHEMA.md` is a 3-line stub (`# Schema\n\nPages use YAML frontmatter with type, and name (entities) or title (documents).`) — never exercises truncation, and predates/duplicates what the entity-schema catalog now expresses structurally.
- **No RESOLVER.md exists anywhere in this repo** (no fixture, no docs example file) — the RESOLVER.md discussed at length in `docs/entity-resolution.md` is a critical read of an *external, real user's own vault's* RESOLVER.md, used as design research, not something wakil ships.
- `docs/entity-resolution.md:23-45` documents that real RESOLVER.md as a **ten-rule priority waterfall** (first-match-wins) that is far more than a directory lookup: rule 1 is a sensitivity override that pre-empts everything else; rule 5 vs. 6 (project vs. concept) is disambiguated by an explicit owner/due-date test with a `split` escape hatch for mixed content; there's a dedicated linking-convention rule (absolute paths only); and (per `src/wakil/skills/note-routing/SKILL.md:56-81`, wakil's own design response to this) RESOLVER.md is expected to carry **subject-matter subdirectory routing** ("file by primary subject, not format/source") and a **sui-generis-synthesis exception**, none of which a flat `directory:` string can express.
- The critical read also documents real RESOLVER.md failure modes that are judgment gaps, not schema gaps: rule 8 (`organization`) is structurally pre-empted by rule 6 (`concept`) because of first-match-wins ordering (finding #2); the document claims total authority but only routes ~10 of ~20 real top-level directories (finding #5); `inbox/` is prescribed but doesn't exist (finding #6); no stated raw-to-synthesized promotion threshold for meetings vs. sources (finding #9).
- Conclusion from direct evidence: **workspace placement routing is not fully covered by `schema.directory`.** `schema.directory` gives a single canonical directory per *entity type* (deterministic, code-owned — `note-routing/SKILL.md:31-40` explicitly calls this "not a judgment call"). RESOLVER.md's job, per `note-routing/SKILL.md:42-54`, is explicitly scoped to **everything that is not a single resolved entity** — raw sources, synthesized notes, journal entries, meeting records — and covers subject-based sub-routing, sensitivity overrides, naming conventions, and hard-call disambiguation that the YAML schema catalog has no field for at all.
