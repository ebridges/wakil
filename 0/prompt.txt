### The merged `_build_traversal_sql` design choice

I think this is the right call, and for the reason given rather than just habit. The seed/step fragment assembly and the `WITH RECURSIVE` template are tightly coupled — the template's structure (`walk(...)`, `best_depth`, the correlated-subquery split to dodge SQLite's "misuse of aggregate MIN()") only makes sense in light of what the seeds/steps produce, and vice versa. Splitting them into two functions would produce two functions whose only real contract with each other is "this string gets f-string-interpolated into that string" — a seam that a unit test can only assert as string equality, not as evidence the CTE walks correctly. The actual correctness net for this file is the 13 tests in `tests/unit/test_graph_service.py`, which already exercise the query end-to-end (out/in/both, cycles, depth clamping, predicate filtering, cross-table isolation from Memory↔Memory rows) — those are unchanged and still the right level to test at. The module's own docstring commitment ("Backed by a single SQLite `WITH RECURSIVE` CTE") plus the historical no-graph-library/no-new-table decision here (a Phase 2 build-out of ADR 0006) supports keeping the hand-written SQL auditable as one block rather than fragmenting it for a testability benefit that's mostly cosmetic.

No new tests were added for the extracted helpers individually — appropriate here, since (a) it's a pure refactor with no behavior change, and (b) unit-testing `_build_traversal_sql`'s string output in isolation would be the same illusory-testability trap the PR explicitly declined to create by splitting further; the existing behavioral suite is the right coverage.

### Proportionality (CLAUDE.md / Prime Directive)

This is a mechanical, behavior-preserving decomposition of one long function into named steps — no new config knobs, no new abstraction layer, no new dependency, no speculative generality. It's the kind of readability refactor the "keep changes small" working agreement is fine with, and it earns its keep simply by making a 150-line function auditable in ~35-line chunks without changing what runs.
