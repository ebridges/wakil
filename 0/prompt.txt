## 3. `src/wakil/config` — WorkspaceConfig / workspace-root

`src/wakil/config/settings.py` defines `WorkspaceConfig(BaseModel)`:

```python
class WorkspaceConfig(BaseModel):
    name: str
    root_path: Path        # this checkout's own directory — used for ALL file I/O
    state_root: Path | None = None   # where .wakil/ lives; defaults to root_path
    git_remote: str | None = None
    qmd_enabled: bool = False
    ingest_directory: str = Field(default="sources")
    generated_directory: str = Field(default="drafts")
```

`root_path` is the field the codebase already uses everywhere as the sandbox/allowed root for file I/O — e.g. `ingest_service.py` uses `config.root_path` as the base for writing raw captures, resolving proposed note paths, loading entity schemas, and (explicitly) as the `kb_root` argument name in `validate_proposal(proposal, kb_root=config.root_path)`. `config.root_path.resolve()` is also used at line 1396 for a resolved-path safety check. This is the natural `allowed_root` to sandbox `@file:` expansion against.

`state_root` is a distinct concept (where `.wakil/` and the DB live — differs only for linked git worktrees) and is NOT the right root for content-file sandboxing.

Loading: `WorkspaceConfig.load(root: Path) -&gt; WorkspaceConfig` (classmethod) reads `.wakil/config.yaml` located via `resolve_state_root(root)`, but overrides `root_path`/`state_root` in the loaded data with the actual resolved paths for this invocation (lines 102–113). CLI commands get this via `_resolve_workspace(ctx)` (in `main.py`, returns a `Path`) followed by `WorkspaceConfig.load(root)`.

`find_workspace_root(start: Path) -&gt; Path | None` walks upward from `start` looking for `.wakil/config.yaml` (via `is_initialized`), which is how the workspace root is discovered when `-w` isn't passed.
