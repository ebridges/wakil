### Problem
wakil's live-model eval suite (`tests/evals/`) grades 12 skills' SKILL.md judgment prose against `eval.json` rubrics using two stochastic LLM calls per scenario (`run_scenario` generation, `grade_transcript` judging). After this session fixed 4 categories of real bugs, the failure rate dropped from ~45-53% to ~21% (10/47 scenarios). The council was asked: what is the highest-leverage next strategy to reduce that ~21% further, and what to do first? A diagnostic showed the 10 remaining failures are mixed — some perfectly deterministic (same rubric item fails every run), others show genuine generation-side variance.

Feynman (first-principles debugging, sonnet; domain-weight seat 1.5x), Socrates (assumption destruction, opus), Ada (formal systems, sonnet).

### Chairman
Synthesizer (this seat) — did not deliberate; audited the completed three-round deliberation and issued the verdict.

### Provider Routing
Degraded to single-provider. All three members ran on Anthropic. The OpenAI seat (`codex_exec`) failed — detection falsely reported codex installed when it was not. The Google seat (`gemini_cli`) failed — the CLI refused headless execution without a trust flag that was not set. Consequence: zero cross-provider diversity; the "epistemic diversity" is persona-level only, all sharing one model family and one set of blind spots (see Scorecard).

### Acceptable Compromises
- **Sample size on the validity check.** Socrates's Round 1 "hand-label 15-20" collapsed to "5-6 scenarios, and only on the deterministic subset" by Round 3 — a proportionate spot-check, not a full grader-calibration study, accepted by all three.
- **Sequencing.** Socrates conceded that cheap mechanical reruns run *first*; the human check is not a blocking prerequisite for the reruns, only for the SKILL.md edits.
- **Variance subset handling.** No human labeling proposed for the variance bucket — it stays "frozen transcript, regrade N times" to localize noise between generation and grading. Accepted without dissent.
- **Scope discipline.** Full grader-vs-human calibration is explicitly deferred, triggered only if reruns reveal verdict flips on identical input.

### Kill Criteria
The verdict (rerun-classify all 10 -&gt; human-validate the deterministic subset -&gt; then edit) is falsified if any of the following is observed:
- **Reruns flip on identical frozen input** (generation or grading) at a material rate — then the clean "deterministic vs variance" partition the whole plan rests on does not exist, and full grader calibration must be escalated immediately rather than "only if."
- **The 5-6 human-labeled deterministic scenarios agree with the grader on all items** — the validity check found nothing, the grader was trustworthy on this subset, and the extra step added latency without protecting the source of truth (weakens Socrates/Ada's dealbreaker for this subset, though not the general precision≠accuracy point).
- **Human labeling itself proves unstable** (the single user cannot self-consistently label the same scenario) — then "ground truth" is not available at this cost and the validity gate is not decidable as designed.
- **Editing SKILL.md to pass a validated rubric measurably degrades real skill behavior** in normal use — confirming that chasing the eval number, even a validated one, is the wrong objective.

### Concrete Next Step
Owner: the engineer running the eval harness (single maintainer). Produce one artifact: a **classification table for all 10 remaining failures**, generated by re-running each failing scenario 5x through the full pipeline and, for every failure, additionally freezing its transcript and regrading it 5x. The table records, per scenario+rubric-item: generation-pass-rate (n/5), frozen-regrade-pass-rate (n/5), and a derived bucket — (a) deterministic content gap [fails 5/5 generation AND 5/5 regrade], (b) generation variance [flips across generations, stable on regrade], or (c) grading variance [flips on frozen regrade]. This table is the mechanical, correctness-agnostic input the entire council agreed must exist before any SKILL.md is touched. Rough scope: a single diagnostic-script extension plus one batch run; hours, not days.

### Unresolved Questions
- **Ground truth is unmeasured.** No one has ever measured `grade_transcript`'s agreement with human judgment. The council does not know whether the grader is accurate, only (soon) whether it is self-consistent. This is the load-bearing unknown.
- **How much of the residual 21% is grader bug vs. real skill gap** is unknown until the classification table exists — and even then, bucket (a) does not distinguish "skill genuinely deficient" from "rubric wrong," which is exactly the failure mode this session already found and fixed once.
- **Whether a lower failure rate is even the right target.** Socrates's premise-challenge (0/47 could mean perfect skills or a grader that certifies nothing) was raised and never fully resolved — the council optimized "how to reduce failures safely" without settling "is this number a valid objective."
- **Provider-diversity blind spot.** With all seats on one model family, an error mode that Anthropic models share (including in the grader, which is presumably also an Anthropic call) would be invisible to this panel. The council cannot self-detect this.
- **Where the variance-bucket noise actually lives** (generation vs grading) is not yet known — the frozen-regrade step is designed to answer it but hasn't run.

### Recommended Next Steps
1. Build and run the classification table (the Concrete Next Step). Gate everything on it.
2. On the deterministic bucket (a) only: hand-label 5-6 scenarios against the rubric items before editing any SKILL.md. Where human and rubric disagree, fix the *rubric*, not the skill.
3. For bucket (a) items where human and rubric agree the skill is deficient, edit SKILL.md as reviewable diffs (per the repo working agreement), same method as the prior 16 fixes.
4. For buckets (b)/(c): do not edit SKILL.md. Use the frozen-regrade result to decide whether the fix is a generation-stability improvement or a grader-prompt/rubric fix.
5. Escalate to full grader-vs-human calibration only if step 1 shows flips on identical frozen input.
6. Separately (infrastructure, not this problem): fix the false provider-detection and the headless-trust-flag issues so future councils are not silently single-provider.
